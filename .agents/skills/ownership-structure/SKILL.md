# 股权结构分析与绘图 Skill（ownership-structure）

## 1. 目标与边界

本 Skill 服务于“企业授信研究Agent”，将**有来源的股权事实**转化为可核验的股权穿透关系、图表及授信报告段落。

- **首测企业**：石家庄以岭药业股份有限公司（002603.SZ）。此处仅为测试对象，**不得预置、编造或假定其股东名单与比例**。
- **第一版数据范围**：公开上市公司年报、定期报告、权益变动和控制权公告、公司公开资料、依法可访问的企业登记公示信息。当前**不支持用户上传资料**。
- **不包含**：直接作出授信审批决定；凭持股比例推断实际控制人；绕过访问限制抓取数据；把股权结构图当作股权登记或法律意见。
- **输出**：`ownership.json`、`ownership_structure.svg`（可选 PNG）、`ownership_summary.md`、`ownership_sources.json`、`ownership_questions.md`。
- **执行前提**：宿主 Agent 能提供公开资料检索/读取、结构化存储和 Python 工具执行。**本文件是 Skill 规则，不会单独自动联网或绘图**。

## 2. 触发条件与输入

在以下任务中使用：股权结构图、股东穿透、控股股东/实际控制人识别、国资背景核查、授信报告“股权与控制关系”章节。

**必需输入**：公司名称或股票代码。优先以证券代码、交易所及公司全称确定唯一主体。

**可选输入**：`as_of_date`（股权信息基准日）、`max_display_levels`、`individual_threshold_pct`、`minor_holder_threshold_pct`、`output_format`。未指定日期时以**最新可核实公开披露时点**为准，并在输出中注明“截至……”，不得将不同日期的数据无说明地混合。

默认参数：

```yaml
max_display_levels: 5           # 包括目标公司所在的第1层；默认最多展示5层
individual_threshold_pct: 25    # 自然人单独展示阈值：严格 >25%
minor_holder_threshold_pct: 5   # 一般小股东合并候选：严格 <5%
output_format: [json, svg, md]
```

## 3. 核心业务规则

### 3.1 先核实主体与披露口径

1. 记录公司全称、曾用名（如适用）、证券代码、交易所、报告期、资料发布日期。
2. 区分**上市公司股东结构**（谁持有上市公司股份）与**集团对子公司的出资结构**（集团持有哪些子公司）：两类关系不能混在同一条未经说明的穿透链上。
3. 年报“前十大股东”不是完整股东名册；不得据此推定未列示股东的姓名、身份或数量。
4. 股权关系与表决权/一致行动/协议控制可能不同；分别记录，禁止直接等同。

### 3.2 穿透方式及终止条件

1. **在数据层面从目标企业出发，沿“被投资企业 → 其股东”向上追溯**，对影响控制关系的重要股东继续穿透。
2. **在图上按用户示例布局**：目标企业位于最上方，第2层为直接股东，第3层为直接股东的上层股东，依次向下展开；连线标注“该股东持有其上方企业的股份比例”。图是“穿透检索方向”，不是对出资权利方向的重新定义。
3. 默认**最多展示5层（包含目标企业）**，不是5次穿透外再加目标企业。穿透超过限制时，图中标注“超过展示层级”，文字说明仍未穿透的主体和原因；必要时可在数据层继续核查，但不得暗示图已完整。
4. 穿透到**自然人**、**依法明确的最终国资监管/政府主体**，或已有权威披露明确的最终控制主体时，可以停止该路径。
5. “国资平台”“国有企业”“基金”“合伙企业”本身**不必然是终点**。如上层所有者未查明，应继续核实或标注“待穿透/资料不足”，不得仅凭名称认定为国资实际控制。
6. 遇到循环持股、重复节点或多条控制链时，用唯一实体 ID 去重并检测环路；允许一名股东连接多家主体，不能把相同主体错误复制成互不相关的公司。

### 3.3 股东展示和合并

以**每一个被持股企业为独立分组单位**处理股东；不同企业的股东不能跨节点汇总。

- **优先单列**：已披露控股股东、实际控制人、一致行动人、可能影响控制权的重要股东，以及监管披露要求特别关注的主体，**无论持股比例是否超过阈值**。
- **自然人股东**：单个持股比例**严格超过25%**时单列；其余自然人**可**合并显示为“其他单个持股不超过25%的自然人股东”。恰好25%的股东原则上属于候选合并组，但如涉及控制关系必须单列。**25%仅是可视化阈值，不是认定实际控制人的法律标准。**
- **一般机构/其他股东**：单个持股比例**低于5%**且不影响控制关系时，可合并为“其他单个持股低于5%的股东”；恰好5%原则上单列。需要保留年报披露的前十大股东以及重大股东的信息时，不应为凑阈值而隐藏。
- **不得强制凑满100%**：仅当可核验该组全部成员、对应比例和同一时点的分母时，才标注聚合后的合计持股比例；否则标注“合计比例待核实”或“未单列股东（比例未知）”。
- 对“其他股东”节点应说明其构成（例如自然人/机构/未明确），不把无法识别的股东擅自归为自然人。
- 若多个自然人为一致行动人或共同控制人，应保留控制关系，不能简单合并后掩盖关键事实。

### 3.4 控制权和国资背景

1. **直接持股比例 ≠ 实际控制比例 ≠ 表决权比例**。控股股东、实际控制人、最终国资主体的结论优先引用公司正式披露及其他可靠公开证据。
2. 对国资背景至少区分“国有股东参股”“国有控股”“国有实际控制”三个不同层次；不得仅因链条中存在国企即断言最终为国资控股。
3. 有协议控制、表决权委托、一致行动安排或无实际控制人的披露时，在数据与文字中单独说明。
4. 无证据时输出“尚无法依据当前公开资料确认”，而非猜测个人姓名、持股比例或国资性质。

## 4. 数据来源与核验

**来源优先级**：交易所/巨潮资讯等官方披露文件（年报、权益变动、控制权公告）→ 公司投资者关系及法定公开资料 → 国家企业信用信息公示系统等依法可查登记资料 → 其他可追溯公开来源。第三方商业资料只能作为线索或补充，不直接替代关键控制关系的核验。

对每条用于绘图的股权连线保存：来源名称、原始 URL、披露日期、报告期/基准日、PDF 页码或定位信息、原文片段（可选）、核验状态。**图中的比例不能脱离证据单独存在。**

核验规则：
- 优先同一时点比较；若股东关系发生变化，应注明采用哪一期披露。
- 同一股东持股比例存在冲突时，优先比较基准日期与更正公告，未解决前标记 `conflicted`，不得挑选数字静默覆盖。
- 若百分比无法确定，不得臆算；所有比例必须带单位 `%`，并检验 `0 <= pct <= 100`。
- 可检查已知直接股东比例之和是否超过100%；低于100%不自动判错，因为可能只披露部分股东。
- 每个实际输出的节点、连线与结论至少指向一个来源 ID；聚合节点则指向其可验证的构成及计算来源。

## 5. 标准工作流

1. **识别企业**：确认唯一上市主体、证券代码和研究基准日。
2. **检索披露**：优先读取最新可用年报及其后的控制权/权益变动公告，必要时追溯上层股东公开资料。
3. **提取事实**：将股东名称、统一实体标识、持股比例、股权/表决权关系、时点、来源整理为结构化候选关系。
4. **事实核验**：核对冲突、名称重名、数据单位和日期；不能确认的关系保持空值并加入待核实清单。
5. **逐层穿透**：优先重大/控制性股东，按第3节终止和层级规则构建关系图。
6. **合并小股东**：仅对不影响控制权判断且合计可解释的同层股东进行可视化聚合；保留底层原始记录，不因合并删除数据。
7. **绘制股权图**：调用 Python + Graphviz 工具，由结构化数据确定布局，目标企业在图顶端，股东逐层向下展示；显示每条边的持股比例和不确定状态。
8. **生成说明**：形成股权背景、控股股东、实际控制人、国资性质、结构特点和信息限制的中文报告段落。
9. **输出待核查问题**：列出未披露、冲突或超过显示层级的关键关系，说明需要补充哪些公开资料。
10. **执行校验**：确保图中所有关系与 JSON 相符，来源可追溯，文件可打开，不能把缺失数据伪装成已穿透。

输出约定：

| 文件 | 内容 |
| --- | --- |
| `ownership.json` | 完整实体、股权连线、控制关系、聚合标记和不确定状态 |
| `ownership_structure.svg` | 默认主要图，可缩放并嵌入报告；需要时另输出 PNG |
| `ownership_summary.md` | 有引用标注的授信报告股权章节 |
| `ownership_sources.json` | 所有关键来源的 URL、日期、页码/定位信息 |

```text

```

绘图工具应接收经过校验的数据，不自行通过 LLM 随机生成股东名称或比例。

## 7. 图表规范

- 目标企业位于顶部；股东沿图从上至下依次排布，默认不超过5层。
- 节点显示名称，连接线标注“持股 xx.xx%”；比例未知时显示“持股比例待核实”，不得填0。
- 通过节点形状/浅色标签区分：目标公司、自然人、政府/国资监管主体、国有企业/平台、民营企业、基金/合伙企业、聚合股东、未核实主体。
- 目标主体和已确认实际控制主体可适度强调，但**不得通过颜色暗示尚未证实的控制性质**。
- 复杂情况下保证图表可读，优先合并、折叠非关键分支；图下注明折叠策略与未穿透原因。
- 所有缩写、合并与截断应在图注或附表中解释。

## 8. 错误与边界处理

- **未取得官方文件**：明确检索失败和已尝试来源，输出可用链接或检索建议，不得补写股东结构。
- **披露只到前十大股东**：标记“部分股东名单”，不能误称全部股东。
- **存在重大冲突**：保留不同来源与日期，输出冲突提示，暂缓相关股权图结论。
- **股东未穿透到终点**：输出“未完成穿透”并说明层级限制或资料不足。
- **超过五层**：折叠超过部分，保留“尚有上层股东”的提示，不得标为已到最终自然人/国资主体。
- **无实际控制人**：只有正式披露证据支持时才写“无实际控制人”；否则写“无法确认实际控制人”。

## 9. 测试与验收

必须使用**人工构造的虚构股权案例**进行单元测试，再用以岭药业公开资料做端到端验证。至少覆盖：

1. 一至五层结构均能绘图，目标公司始终在顶部。
2. 超过五层时截断并提示，不能被误判为穿透完整。
3. 自然人 24.99%、25.00%、25.01% 的边界处理正确（重要控制人始终单列）。
4. 机构股东 4.99%、5.00%、5.01% 的边界处理正确。
5. 聚合比例仅在原始数据完整时计算；不允许补足到100%。
6. 国资参股与国资控制能够区分，未知控制权输出 `unknown`。
7. 存在一致行动、表决权委托、复杂基金及交叉持股时保留风险提示。
8. 不同报告日期的冲突能够被发现，不能静默混用。
9. 任意绘图边均有来源 ID；未核实来源明确标记。
10. 图、JSON 和文字叙述保持一致；SVG 可成功渲染。

**以岭药业端到端验收**：在可访问公开资料的条件下，识别 `002603.SZ`，从公开披露提取实际股东和控制信息，生成带来源的图及文字。**不得将上述虚构 JSON 示例冒充实际结果。**

## 10. 运行时集成说明

- 在 Codex 中，该目录的 `SKILL.md` 可用于指导开发/研究任务，相关脚本需由工程实现。
- 若产品采用 OpenAI Agents SDK 运行，**不会仅因为放入 `SKILL.md` 就自动具备技能选择能力**；需要主 Agent 实现 Skill 元信息发现、按需加载，以及相应工具注册或明确的调度机制。
- 本 Skill 遵循“有来源的事实 → 校验 → 穿透与聚合 → 确定性绘图 → 文字解释”的顺序，不允许直接依据 LLM 想象输出股权图。
